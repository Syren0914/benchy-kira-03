# Contributing to KIRA

Contributions are welcome as the project prepares for a reproducible public release. Begin with the documentation status and confirmed hardware revision in the README.

## Report a build issue

Include the hardware revision, documentation version, exact component models, substitutions, the step you followed, expected behavior, observed behavior, and measurements with units and test conditions. Include relevant photographs with personal information removed. Do not operate an unsafe assembly to collect more evidence.

For an electrical safety concern, stop using the affected build and describe the concern clearly. The maintainer should place confirmed critical errata prominently in the README and affected release documentation.

## Propose a change

Explain the problem, affected revisions, change, compatibility impact, and validation performed. Update the schematic, wiring schedule, BOM, CAD, photographs, and instructions together when they are affected. Identify the source and license of contributed material. Do not include files you lack permission to redistribute.

## Documentation improvements

Useful contributions include clearer assembly photos, verified sourcing alternatives, corrections to connector orientation, translations, and independent build reports. Preserve warnings, numerical limits, revision labels, and source attribution when translating.

The project's contribution licensing policy must be finalized alongside its license choice before accepting code or design contributions for public redistribution.
